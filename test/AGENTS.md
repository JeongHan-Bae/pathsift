# Test instructions

Tests use Node's built-in test runner. Focused tests live in `test/tdd/`; executable CLI scenarios live in `test/bdd/<command>.test.mjs` with a matching `<command>.feature`. Feature files document scenarios but are not executed by Cucumber. Every CLI command has its own BDD file. The path-processing commands `tree`, `ls`, `find`, `count`, `du`, `hash`, `manifest`, `cp`, and `archive` must each cover the shared fixture matrix: 0, 1, and 2 ignore files, two files with `--no-global-ignore`, and two files with `--no-ignore`.

TDD for a structured document checks its fields and contracts without freezing presentation wording or order. BDD owns the final serialized CLI text.

BDD tests run child processes and assert complete observable results: stdout, stderr, exit status, and produced files or archives. Keep expected paths and content in the fixture, independent of the implementation walker. `tree` BDD owns exact branch order: directories first at every level, then files and symlinks, with names sorted inside each group. Use temporary directories and remove them in `finally`. Never use a contributor's files or the repository's `global.ignore` as a fixture. Preserve symlink and destination safety assertions, including with `--force`. Export BDD must cover missing, empty, and nonempty targets inside the source. Adapter TDD must force failures in both memory and direct modes and verify rollback. Inspect real archive members rather than checking only file existence.

The same BDD files run in three modes. `test:source` invokes the checkout launcher, which executes native TypeScript on Node 24+ and compiled JavaScript on Node 22 and 23. `test:compiled` invokes the compiled CLI entry directly. `test:package` packs and installs the npm artifact, then invokes its compiled entry. Do not inject application ports into BDD tests. A launcher TDD test checks which branch was selected for the running Node version.

Interactive terminal cases use `node-pty`, a development dependency. They operate on a temporary package copy and never edit the repository's config. Check both TTY styling and plain pipe output. `nano` scenarios cover non-TTY refusal, save, discard, and invalid arguments. JSON output must remain parseable and unstyled even on TTY. The `hash` BDD must prove that both a visible rename and a transfer of bytes across two visible files change the tree digest; the first-level file digest must bind filename and content hashes. Relocating an unchanged user-selected scan root must preserve both file and tree hashes because names are relative to that root. Selecting a nested root changes those relative names. Update feature text and executable assertions together when behavior changes.
