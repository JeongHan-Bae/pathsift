# Build and package

`src/` is TypeScript. `npm run build` removes stale `dist/`, compiles with `tsconfig.json`, rewrites relative `.ts` imports to `.js`, and marks `dist/boot/cli-main.js` executable. `tsconfig.json` requires erasable TypeScript syntax so Node 24+ can execute the same source without a loader. Node 22 and 23 execute compiled JavaScript through the checkout launcher.

The npm `pathsift` bin is `./dist/boot/cli-main.js`. The repository root is private; its `README.md` describes the GitHub project. `scripts/package-artifact.mjs` builds a temporary publishable directory from the root manifest's production fields and `files` allowlist. It copies `docs/npm-readme.md` into that directory as `README.md`, and omits development scripts, development dependencies, and the private flag from the generated manifest. The artifact contains `dist/`, `README.md`, `LICENSE`, `docs/architecture.md`, `docs/hash.md`, `pathsift.config.json`, `global.ignore`, and npm's `package.json`. It excludes `src/`, the checkout launcher, tests, CI, development docs, and TypeScript tooling.

Run `npm run stage:release` to create the Git-ignored `release-preview/` directory from a real tarball packed from the generated publishable directory. It contains the `.tgz`, an extracted `package/` tree, and `pack-metadata.json`. The staging script verifies the extracted file list against npm metadata and refuses to replace a directory without its generated marker. `npm run check:package` verifies the exact file list against the generated `dist/` tree, checks that the package README comes from `docs/npm-readme.md`, and rejects TypeScript source and repository-only manifest fields. `npm run test:package` packs the same generated directory, installs it in a temporary consumer project with production dependencies, checks the installed bin target, and runs the per-command BDD suite against that installation. Direct `npm pack` or `npm publish` from the repository root is refused; publish only the reviewed tarball under `release-preview/`.

The CLI loads `pathsift.config.json` and `global.ignore` relative to the installed package root. The shipped config must explicitly declare the supported `hashVersion` and positive `bufferLimitBytes`. Export data is buffered in memory at or below the configured visible-file byte limit and written directly above it; a failed output is removed or reset to its originally empty state. `pathsift nano` requires write access to the installed package directory; users who need it should install under a user-writable npm prefix. Other commands can read a system-owned installation.
